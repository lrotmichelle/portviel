The module is split into two layers: `src/types.ts` and `src/types/*.ts` define shared interfaces (`Order`, `Offer`, `CampaignCardData`, `MarketCardData`, `SalesCardData`, negotiation session/event types) consumed across the app; `src/lib/*.ts` are feature-scoped service modules that query the database via Drizzle ORM through a single `@/db/schema` model. Data access goes through `src/lib/db.ts`, which re-exports `db` and `pool` from `@/db/client` under a `server-only` guard, and through `src/lib/prisma.ts`, which exposes a Prisma-like `prisma.{campaign,vacancy,marketListing,engagementEvent}` API built on top of Drizzle queries with normalized ordering, pagination, and optional member joins. Each feature file (e.g. `campaigns.ts`, `market.ts`, `negotiation.ts`) encapsulates one domain area: it maps raw DB rows into typed DTOs and exports async fetch functions used by UI components. Utility helpers live in `utils.ts`, `currency.ts`, `finance.ts`, and `office-history.ts`. There is no runtime framework — this is a pure TypeScript library layer depending only on `drizzle-orm` and the project's `@/db/*` package.
