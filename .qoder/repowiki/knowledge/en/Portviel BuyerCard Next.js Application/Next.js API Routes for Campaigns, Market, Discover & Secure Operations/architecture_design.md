Each subdirectory under `src/app/api/` is a Next.js Route Handler (`route.ts`) exporting `GET`/`POST` handlers with `runtime = 'nodejs'` and `dynamic = 'force-dynamic'`. Data access goes through `@/lib/db` (Drizzle ORM) and `@/db/schema`; business logic is delegated to sibling libraries like `@/lib/discover`, `@/lib/market`, `@/lib/negotiations`, and `@/lib/profile`. The `campaigns/` route handles listing and creation of campaigns; `campaigns/manage/route.ts` is a multi-action handler dispatching on `action` (`create`/`update`/`pause`/`resume`/`delete`) with ownership checks against `createdBy`. `discover/route.ts` reads from the `vacancies` table and also accepts POST to create new vacancies. `market/route.ts` provides listing cards and a POST that validates social-profile URLs via an internal `verifySocialAccount` function (special-casing Instagram's GraphQL endpoint and falling back to HTML scraping), then persists to `marketListings`. `negotiations/route.ts` and `profile/route.ts` are thin GET wrappers around library functions. `secure/route.ts` is the central write-heavy endpoint: its POST dispatches on `mode` (`create_discover`, `create_campaign`, `create_market`, `pause_vacancy`, `delete_vacancy`, `pause_campaign`, `delete_campaign`, `pause_listing`, `update_listing`, `delete_listing`, `interact`, `update_campaign`, `update_campaign_status`, `approve_campaign_submission`) and records every mutation as an `engagementEvents` audit row. Identity is inferred from the `x-user-id` header or request body fields, with role inferred from `x-user-role`. All routes wrap their bodies in try/catch and return `NextResponse.json` with consistent `{ ok, item, error }` shapes and HTTP status codes.
