Three sibling route components under `src/app/campaign/` form the campaign feature surface: `campaign.tsx` is a standalone mobile-only list (no Next.js page), `page.tsx` is the desktop/multi-screen campaign discovery page, and `activity/page.tsx` is the `/campaign/activity` route showing joined campaigns plus an activity feed. All three are client components that fetch data from internal REST endpoints (`/api/campaigns`, `/api/secure`, `/api/profile`) using `fetch` with an `x-user-id: demo-user` header, then render shared `CampaignCard` items from `@/components/campaign-card`. Stateful filtering/search/sort logic runs entirely in React `useState` on the client; server-side rendering is not used for these routes. Cross-page navigation between Campaigns, Joined, and Manage views is done via Next.js `<Link>` to `/campaign`, `/campaign/activity`, and `/campaign-manager/manage`. Modal-driven creation flows reuse `CampaignModal` and `AdvertModal` from `@/components/layout`, and mock fallback data comes from `@/lib/mockCampaigns.generateMockCampaigns` when the API is unavailable.
