Each subdirectory under `src/app/api/` is a Next.js Route Handler (`route.ts`) exposing `GET`/`POST` handlers with `runtime = 'nodejs'` and `dynamic = 'force-dynamic'`. The routes are organized by domain: `campaigns/route.ts` (list/create), `campaigns/manage/route.ts` (action-driven create/update/pause/resume/delete with ownership checks via `createdBy`), `discover/route.ts` (read via `@/lib/discover`, write to `vacancies`), `market/route.ts` (read via `@/lib/market` with dynamic import fallback, write with social-profile verification against Instagram/TikTok/etc.), `negotiations/route.ts` and `profile/route.ts` (thin GET wrappers around `@/lib/negotiations` and `@/lib/profile`), and `secure/route.ts` (a unified POST endpoint dispatching on a `mode` field across campaigns, vacancies, market listings, and engagement events). All routes read/write through Drizzle ORM using schemas from `@/db/schema` and the shared `db` client from `@/lib/db`; user identity is extracted from the `x-user-id` header or request body with a `demo-user`/`anonymous` fallback. Read-heavy routes return JSON arrays or objects; write-heavy routes validate input via local `toString`/`toNumber`/`parseArray` helpers and respond with `{ ok, item }` or `{ error }` payloads. Error paths consistently log via `console.error` and return 400/401/403/404/500 JSON responses.
