Two cooperating React contexts form the state layer: `NotificationContext` (src/context/NotificationContext.tsx) owns the shared `Order[]` / `Offer[]` lists plus seen-flag UI state and persists them to `localStorage` keys `orders` and `offers`; `NegotiationContext` (src/context/NegotiationContext.tsx) wraps those via `useNotificationContext()` to drive a full negotiation FSM (`idle | buyer-pending | seller-pending | accepted | payment-pending | declined | timed-out | passed | finalized`) over per-card `NegotiationSession` objects, also persisting sessions, notifications, and an event log under dedicated `negotiation-*` storage keys. A 30-second `setInterval` tick enforces 1-day expiration and cooldown timers, transitioning pending sessions to `passed` or `timed-out` and syncing back into the notification context's order/offer arrays. The `hooks/` directory exposes thin wrappers: `useNotification` re-exports `useNotificationContext`, and `useNegotiationManager` provides higher-level business operations (create order, accept/counter/decline from either side) that mutate the same `orders`/`offers` arrays without touching the session FSM. Dependency direction is one-way: NegotiationContext depends on NotificationContext; hooks depend on contexts; no cross-imports between contexts beyond this single dependency.
