Three sibling card components share a consistent internal layout: `offer-card` and `order-card` are composed of four sub-components (`header`, `content`, `sentiment`, `footer`) plus a `types.ts` defining the card's data shape, while `buyer-card` is a single-file component. Each card is a `'use client'` React component that owns local UI state (counter form visibility, validation errors, payment panel toggles, verification timers) and exposes callbacks (`onAccept`, `onCounter`, `onDecline`, `onCounterToggle`, `onFinalize`, `onRefreshData`) to parent containers for side effects. Both `offer-card` and `order-card` integrate with a shared `NegotiationContext` (`@/context/NegotiationContext`) to read/write negotiation sessions keyed by card id, deriving active status, pricing, and inactivity from session state. The offer card additionally supports an inline mobile-money checkout panel with a simulated verification flow using a `setTimeout` timer and a `Loader2` spinner. All three cards use Tailwind utility classes for styling and `lucide-react` icons for visual cues; `buyer-card` additionally uses `formatCompactValue` from `@/lib/currency` for number formatting.
